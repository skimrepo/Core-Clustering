# 전체 시계열(윈도우 없음) + Conv-Bottleneck + Self-Attention 아키텍처 설계 기록

Date: 2026-08-18

이 문서는 RedLamp/Core-Clustering의 기존 윈도우 기반 `ConvAEC`와 완전히 별도인 새 병렬
아키텍처(`core_clustering/models_conv_bottleneck.py` 등)를 설계하면서 오간 논의와 결정 사항을
시간 순으로 기록한다. **RedLamp는 절대 수정하지 않는다** (레퍼런스로 계속 사용할 목적) — 이번
작업은 전부 Core-Clustering + AnomSim(`ShiftAnomaly`, `anomsim_v3_*`)에만 반영됨.

## 1. 배경 — 왜 이 작업을 시작했나

- 기존 RedLamp/Core-Clustering 아키텍처는 고정 길이 윈도우(기본 100 timestep)를 잘라내
  12-way 분류를 학습. 목표: **윈도잉을 없애고 가변 길이 시계열 전체를 한 번에 입력받아
  매 시점(timepoint)마다 정상/이상을 직접 판정**하는 모델.
- 배경 동기: 실제 타겟 도메인(예: 반복 생산되는 웨이퍼 측정 데이터)은 "도메인 전형적 길이"가
  존재해서, 윈도우 단위 분류보다 전체 시계열 단위 처리가 더 자연스러움.
- 1차 실험 데이터: AnomSim에 신규 추가한 `white_noise` 전용 `AnomSim_v3` (길이 500~550,
  새 anomaly 타입 `ShiftAnomaly` — 랜덤 위치/길이(5~50%) 구간에 `±2×clean_std` 상수 오프셋).
- 모델 출력: 2-head 구조 — Head1(재구성, masked MSE), Head2(시점별 이상 여부, BCE).

## 2. 아키텍처 1차 시도: 다운샘플링 없는 TCN → 폐기

- 처음엔 dilated residual TCN block(같은 해상도 유지, `padding='same'`)으로 설계 — 가변 길이
  자연 지원이 목적.
- **문제 발견**: 병목(정보 압축)이 전혀 없어서, masked MSE reconstruction이 residual/skip
  connection을 타고 **입력을 그대로 베끼는(copy-through) 전략으로 수렴**함. 실측:
  `train_loss_ae`가 0.44 → 0.0003까지 떨어짐 — 화이트노이즈처럼 학습 가능한 시간적 구조가
  없는 도메인에서는 특히 이 문제가 두드러짐 (백서/논문에서도 아니고 실측으로 확인).
- 이 상태에서는 reconstruction이 "정상 구조를 학습"한 게 아니라 그냥 장식용 숫자.

## 3. 아키텍처 2차: Conv-Bottleneck (현재 채택, 검증 완료)

- **결정**: TCN(dilated, no-downsample) 폐기, RedLamp 원래 `ConvEncoder`/`ConvDecoder`와
  같은 계열(비-dilated, stride-2 conv)로 회귀하되, **가변 길이 지원은 유지** — `ConvDecoder`의
  옛날 `nn.Linear(1, compressed_len)`(학습시점 길이에 고정) 방식은 쓰지 않고,
  `ConvTranspose1d(..., output_size=...)`로 **매 forward마다 실제 입력 길이에 맞춰 동적으로
  복원**하도록 새로 구현.
- 채널 폭이 늘어나는 stride-2 다운샘플링만으로는 "압축"이 안 될 수 있음을 테스트가 잡아냄
  (시간축은 줄어도 채널이 그보다 더 빨리 늘면 총 element 수가 오히려 증가) → **명시적인
  channel-squeeze "waist" 레이어**(`bottleneck_channels`, 기본 4)를 인코더 끝/디코더 시작에
  추가해서 진짜 용량 제약을 걺.
- **검증 결과** (AnomSim_v3 2000 인스턴스 스모크 테스트, `bce_loss_ratio=0.2`):
  - `train_loss_ae`가 이제 0.99 → 0.65 선에서 **정체**(더 이상 0으로 안 떨어짐) — 병목이
    실제로 작동한다는 신호.
  - Held-out test에서 **재구성 오차가 정상 구간(0.60) vs 이상 구간(4.96)으로 8배 차이** —
    reconstruction이 이제 진짜 이상 신호로 쓸 수 있는 상태.
  - 탐지 성능: 인스턴스 정확도 99.67%, mean IoU 0.966 — TCN 버전(IoU 0.994)보다 살짝
    낮지만 여전히 강하고, 계산량은 10배 저렴(epoch당 21초 → 2초).

## 4. MSE(재구성)의 실효성에 대한 논의 — 미해결/추후 검토 항목

- 화이트노이즈는 시간적 구조가 없어서, masked MSE reconstruction이 배울 수 있는 최선은
  "로컬 평균/분산 추정" 정도 — 이건 BCE head가 라벨로부터 이미 직접, 더 정확하게 배우는
  정보와 상당 부분 겹침. 병목 덕에 완전히 죽은 신호는 아니지만(위 8배 차이), marginal
  value는 제한적.
- **제안된 대안 (아직 미구현)**: raw Y를 복원하는 대신, **로컬 오프셋/레벨 함수를 회귀**하는
  걸로 head1의 타겟을 바꾸자는 아이디어 — target = 0(정상 구간) / 실제 주입 offset 값(이상
  구간, AnomSim_v3의 `meta.json`에 이미 저장돼 있어 공짜로 사용 가능). 장점: (a) 학습 가능한
  타겟(노이즈가 아니라 구간별 상수), (b) BCE와 직접 시너지(방향/크기까지 추가 지도), (c) 입력
  자체를 그대로 베껴서는 이 loss를 못 맞추므로 copy-through 문제가 원천적으로 사라짐(병목과
  별개로). **다음 세션에서 이어서 결정/구현할 것.**

## 5. Receptive Field / Self-Attention 논의

### 5.1 실측: 넓은 이상 구간의 "dead zone" 우려는 기각됨

- 이론적 우려: shift 구간이 시리즈 길이의 최대 50%까지 허용되는데, 로컬 conv의 effective
  receptive field는 실측 ±30~40 timestep 정도뿐이라, 아주 넓은 shift의 한가운데는 정상 구간과
  비교할 신호가 약할 것이라 예상.
- **실측 결과**: 실제로는 문제 없음 — shift 경계에서 10칸만 벗어나면 recall이 99.9~100%
  (경계 근처만 91.9%, 이건 그냥 boundary 정밀도 문제).
- **이유**: z-score 정규화가 "정상 = 평균 0, 표준편차 1"이라는 **고정된, 학습 데이터 전체에서
  못 박힌 기준**을 제공하기 때문 — 모델이 "이 시리즈의 다른 곳과 비교"할 필요 없이 "학습 때
  배운 고정 기준과 로컬 이웃만 비교"하면 되는 훨씬 쉬운 문제였음.
- **다만**: 실제 도메인(웨이퍼 등, 인스턴스마다 로컬 베이스라인/트렌드가 달라서 고정
  정규화로 "정상"을 못 박을 수 없는 경우)에서는 이 가정이 깨질 수 있음 — 그때는 진짜 인스턴스
  내 장거리 비교가 필요해질 수 있으므로, self-attention을 **범용성 확보 차원**에서 지금
  아키텍처에 상시 컴포넌트로 넣어두기로 함.

### 5.2 주기(periodicity) 관점 — 왜 self-attention이 유용한가

- 압축은 "먼 거리를 압축된 좌표계에서 가깝게" 만들어줌 — 주기 100은 16배 압축 시 6칸 차이라
  로컬 conv로 충분. 주기 3000은 187칸이라 여전히 멀고, 로컬 conv로 닿으려면 압축을 30배 더
  세게 걸어야 하는데 그러면 디테일/위치 정밀도가 심하게 희생됨.
- Self-attention은 압축 정도와 무관하게 임의의 두 위치를 1스텝(내적)으로 직접 비교 — 압축을
  더 세게 걸지 않고도 긴 주기를 다룰 수 있음.
- 짧은 주기(예: 10)와 긴 주기(예: 3000~10000)는 **파이프라인의 서로 다른 지점**에서 자연히
  처리됨 (짧은 건 초반 고해상도 conv, 긴 건 병목 근처 attention) — 문제는 그 중간 스케일이
  애매하게 낀다는 것.

### 5.3 비용 실측 (T=550, 4-stage stride-2 기준)

| 위치 | 시퀀스 길이 | attention 비용(T²) |
|---|---|---|
| 최고 해상도 | 550 | 302,500 |
| | 276 | 76,176 |
| | 139 | 19,321 |
| | 70 | 4,900 |
| 병목 | 36 | 1,296 |

- 모든 레이어에 넣으면 병목만 넣을 때보다 **624배** 비쌈, 최고 해상도 한 곳만 넣어도 **233배**.
- Stable Diffusion U-Net도 이 이유로 attention을 최고 해상도엔 안 넣고 다운샘플된 해상도에만
  넣음 — 우리도 같은 원칙 적용.
- **1차 결정**: 뒤쪽 3단(가장 압축된 3개 해상도)에만 attention. 이후 논의에서 최종적으로
  "T ≤ threshold" 규칙(아래 5.5)으로 재조정.

### 5.4 첫 스테이지는 반드시 `stride=1` (stem) — aliasing 방지

- **문제**: stride를 처음부터 크게(4, 12 등) 걸면, 짧은 주기(예: 3~5)가 그 첫 압축 홉에서
  **aliasing**될 위험이 있음 — 다운샘플링 stride와 신호의 실제 주기가 우연히 맞아떨어지거나
  가까우면, 위상(phase) 정렬에 따라 주기 자체가 완전히 다른 모습으로 왜곡되거나(가짜 주기),
  아예 사라져 보일 수 있음 (Nyquist/aliasing, 표준 신호처리 이슈). 저역통과 필터를 걸어도
  주기가 새 샘플링 레이트보다 짧으면 근본적으로 복구 불가능한 정보 손실.
- **결정**: **첫 스테이지는 항상 `stride=1`(다운샘플링 없음, "stem" 역할)** — 짧은 주기가
  안전하게 feature로 인코딩될 기회를 준 뒤에야 다운샘플링 시작. Stem 레이어 개수는
  `num_stem_layers`로 파라미터화(기본 1), stride>1인 실제 압축 스테이지는 그 다음부터.
  Stem 레이어에는 attention을 절대 넣지 않음(최고 해상도라 비용 문제 그대로 적용).

### 5.5 최종 attention 배치 규칙 — "T ≤ threshold인 스테이지엔 전부" (인터리브 아이디어 폐기)

- **1차로 냈던 "병목에서부터 하나 건너 하나(인터리브) + 비용 상한" 규칙은 폐기.** 인접한
  저렴한 스테이지끼리 굳이 하나를 건너뛸 근거가 없었음 — 이미 싸면 다 붙여도 손해 없음.
- **최종 규칙**: `attention_max_resolution`(기본 256) **이하인 모든 스테이지**(stem 제외)에
  attention 배치. Stem(`stride=1`, 최고 해상도)은 절대 대상 아님.
- **왜 256인가 — 비전과 비교해서 검증**: 비전 쪽 U-Net/Diffusion 계열은 attention을 흔히
  32×32(2D) 해상도까지 씀 — 이건 32×32=**1024개 위치**를 서로 비교하는 거라 비용은
  1024²≈1,048,576. 우리 1D 시계열에서 256개는 256²≈65,536 — **비전이 일상적으로 쓰는 비용의
  1/16도 안 됨.** 시계열은 2D가 아니라서 "토큰 개수" 기준으로 비교하면 비전보다 훨씬 여유가
  있다는 게 실측으로 확인됨. (512~1000 근처까지 가도 비전의 32×32보다 쌈.)
- **결과**: T=550(stem 이후 3단, 대략 139/70/36)은 전부 256 이하라 **3단 다** 붙음 (기존
  "뒤쪽 3단" 결정과 결과가 같아지지만, 이번엔 하드코딩된 "3"이 아니라 비용 기준에서 자연스럽게
  나온 숫자). T=100,000(6단, 대략 25000/6250/1562/390/98/24)은 256 이하인 98, 24만 붙음
  (비용 98²+24²≈10,180, 사실상 공짜). 규칙 하나로 두 극단이 다 자연스럽게 처리됨, 네트워크가
  더 깊어져도 별도 로직 없이 자동으로 확장됨.

## 6. `n_time_max` 기반 자동 깊이 계산 (파라미터화)

- 스테이지 수를 사람이 리스트로 안 넣게, 아래 공식으로 자동 계산:
  ```
  num_stages = max(3, ceil(log(n_time_max / target_bottleneck_len) / log(stride)))
  ```
  (최소 3 — attention 배치할 스테이지가 항상 존재하도록)
- `stride`(스테이지당 압축 배율, 기본 4), `target_bottleneck_len`(병목 목표 길이, 기본 32).
- 채널 폭(`num_filters`)도 리스트를 직접 안 받고 `channel_base`(기본 16)에서 매 스테이지
  2배씩, `channel_max`에서 캡 거는 공식으로 자동 생성.
- **주의**: `n_time_max`는 "혹시 몰라서" 크게 잡는 값이 아니라 **실제 타겟 도메인의 진짜
  최대 길이**를 반영해야 함 — 이 값으로 깊이가 정해지므로, 훨씬 짧은 시계열을 같은 모델에
  넣으면 과압축으로 망가질 수 있음. 도메인이 바뀌면 `n_time_max`만 새로 잡아주면 나머지는
  자동으로 따라옴 (이게 "범용 아키텍처"의 핵심 설계 의도).
